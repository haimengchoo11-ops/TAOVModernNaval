# 俄罗斯海军武备检索 × TAOVModernNaval 改进意见

**检索日期**：2026-10-30（本轮实际抓取的页面见 §6）
**对照工程**：`taovmodernnaval` 1.0.0-SNAPSHOT，MC 1.20.1 / Forge 47.3.0 / Java 17
**口径**：只写本轮**真正读到过**的数字；读不到的写「未核」，不猜、不平均。mod 侧数值全部来自源码，不是推测。

---

## 0. 结论先行

1. **型号层**：11 型「P 系列」里，能在公开谱系中对上号的只有 7 型（P-1 / P-15 / P-120 / P-270 / P-500 / P-700 / P-800）。
   `P-30` / `P-45` / `P-100` / `P-300` 在本轮检索的苏俄反舰导弹条目里都找不到对应实装；其中 **P-300 与 S-300 防空系统撞号**，误读成本最高。
   `p500_missile` 的中文名写成「花岗岩」——**花岗岩是 P-700（Granit）**，P-500 是「玄武岩」（Bazalt）。
2. **参数层：速度排序与真实世界相反**。真实是 P-15 亚音速 Mach 0.9、P-270 Mach 2–3、P-800 Mach 2.0–2.5、P-700 Mach 1.6；
   mod 里 P-15 最快（2.48 格/tick），P-700 / P-800 最慢（1.76 / 1.80）。**快慢关系整个反过来了**。
3. **CIWS 层：射速关系也反了**。真实 AK-630 是 4000–5000 发/分，AK-230 是 2×1000 发/分（AK-630 快 2–2.5 倍）；
   mod 里 AK-230（2 tick/发）比 AK-630（4 tick/发）**快一倍**。
4. **机制层缺三样东西**：弹道剖面（真实掠海 7–20 m、末段俯冲）、制导分段（惯性 → 中制导 → 末制导主动雷达）、齐射/领弹；
   CIWS 没有弹药与过热，命中即秒杀在飞导弹。
5. **缺口层**：防空只有 5V55RM / 9M33（Osa）/ 9M38 三型 + 两门近防炮，
   **3–15 km 这一段（Kashtan、Pantsir-M）与中程 Shtil-1 是空的**；传感器只有「一部雷达 + 一个指挥仪」，
   而真实舰是搜索（MR-800）、跟踪（MR-710）、制导（3R41）、近防火控（MR-123 / MR-104）分工。

## 3. 对照：哪些地方失真

### 3.1 型号命名（P0，纯文本改动，但错得最显眼）

| 现状 | 问题 | 建议显示名 |
|---|---|---|
| `p500_missile` =「P-500 花岗岩」 | **花岗岩是 P-700**；P-500 是玄武岩 | 「P-500 玄武岩反舰导弹（SS-N-12）」 |
| `p30_missile` =「P-30 导弹」 | 谱系里查不到 P-30 反舰弹 | 改为 **P-35「进步」**（SS-N-3，高空 300+ km 级）或直接下线 |
| `p45_missile` =「P-45 导弹」 | 查不到 | 改为 **P-70「紫晶」**（潜射）或 **P-1000「火山」**（Bazalt 增程） |
| `p100_missile` =「P-100 导弹」 | 查不到 | 改为 **3M-54「口径」反舰型**（亚超结合） |
| `p300_missile` =「P-300 导弹」 | 查不到，且**与 S-300 防空系统撞号** | 删除，或改为 **P-1000** |
| `9k60_missile` | 9K33 条目里 Osa 的弹型编号是 **9M33**，没有 9K60 | 改 `9m33_missile`（Osa-M 的弹） |
| `9m38_missile` =「山毛榉」 | 9M38 是**陆基** Buk 弹；舰载型是 **Shtil-1 / 9M317ME** | 「Shtil-1 舰空导弹（9M317ME）」 |
| `9k33_missile` =「黄蜂」 | 舰载型编号是 **4K33 Osa-M** | 「Osa-M 舰空导弹」 |

**兼容策略**：**不要改物品注册 id**（会砸存档与配方）。只改 `lang` 显示名 + tooltip 里的真实型号；
新内容用新 id（`shtil1_missile`、`9m33_missile`、`p35_missile`…），旧 id 保留为「历史型号」。

### 3.2 速度：排序整体反了

| 型号 | 真实速度 | mod 速度 | 问题 |
|---|---|---|---|
| P-15 | Mach 0.9 | 2.48（最快） | 亚音速弹被做成全场最快 |
| P-120 | Mach 0.9 | 2.36 | 同上 |
| P-270 | Mach 2–3 | 2.04 | 超音速冲压弹比 P-15 慢 18% |
| P-500 / P-700 | Mach 2.5 / 1.6 | 1.88 / 1.76 | 最慢的两型恰好是真实的重型超音速弹 |
| P-800 | Mach 2.0–2.5 | 1.80 | 同上 |

### 3.3 射程与当量：单调递增，但真实不是

- mod 射程随「代次」单调增（320 → 720 格），真实射程是**弹道相关**且**非单调**（P-800 联合弹道 300 km < P-700 550 km）。
- mod 当量随代次单调增（4.0 → 22.0），真实战斗部质量：P-500 1000 kg > P-700 750 kg > P-120 500 kg > P-270 300 kg > **P-800 200 kg**。
  P-800 现在是全场最高当量（22.0），真实是重型弹里**最轻**的战斗部。

### 3.4 制导与弹道：缺剖面

真实反舰弹是「助推 → 惯性/指令中制导 → 末段主动雷达 + 掠海/俯冲」，
mod 是「直线 + 转向 + 近炸」，没有高度控制，所以「掠海突防」「跃升俯冲」「齐射领弹」这三件苏俄反舰战术的核心都表达不出来。

### 3.5 CIWS：射速反了，而且没有弹药

| | 真实 | mod | 结论 |
|---|---|---|---|
| AK-630 射速 | 4000–5000 发/分（≈3.3–4.2 发/tick） | 5 发/秒（0.25 发/tick 的等效） | 慢了约 15 倍 |
| AK-230 射速 | 2×1000 发/分（≈1.7 发/tick） | 10 发/秒 | 仍是 AK-630 的两倍 |
| AK-630 射程 | 4 km 对空 | 54 格 | 相对关系对（比 AK-230 远） |
| AK-230 射程 | 4 km 对空 / 2 km 对弹 | 40 格 | 缺「对弹射程砍半」这一条 |
| 命中效果 | 单发命中不保证摧毁（需连发覆盖） | 命中即销毁来袭弹 | 过强 |

## 4. 改进意见

> 原则：**保留 id、改显示名；先修排序、再补剖面；机制改动必须能被单测锁住**。
> 每一条都给了落点文件与验收方式，按 P0 → P2 排。

### P0-1 型号与显示名修正（半天）

- 落点：`src/main/resources/assets/taovmodernnaval/lang/zh_cn.json`、`en_us.json`；`MissileProfile` 的工厂方法注释。
- 动作：按 §3.1 表改显示名；在 `MissileItem` tooltip 里加「真实型号 / 服役年份 / 制导方式」三行（数据从新的规格表读，不要硬编码）。
- 验收：`grep` 语言文件无「花岗岩」误标；tooltip 三行齐全。

### P0-2 重建参数表（1 天，最高性价比）

把「代次越大越强」换成**真实排序**。建议引入统一换算，让以后加型号不用拍脑袋：

```text
速度（格/tick） = clamp(1.40 + 0.50 × Mach, 0.9, 3.2)
射程（格）      = clamp(200 + 120 × ln(R_km / 30), 120, 600)
当量（TNT）     = clamp(战斗部总质量_kg / 45, 2, 24)
```

按 1 格 = 1 m、1 格/tick = 20 m/s 计，这套换算能得到下表（保留现有手感区间 1.8–2.5 格/tick、320–560 格）：

| 型号 | 真实 | 建议速度 | 建议射程 | 建议当量 | 备注 |
|---|---|---|---|---|---|
| P-15 | M0.9 / 80 km / 未核 | 1.85 | 235 | 8（待核后定） | 亚音速，最低档 |
| P-120 | M0.9 / 110 km / 500 kg | 1.85 | 356 | 11 | 全程掠海 |
| P-270 | M2.5 / 120 km / 300 kg | 2.50 | 362 | 7 | 末段 <7 m，穿透型 |
| P-500 | M2.5 / 550 km / 1000 kg | 2.50 | 549 | 22 | 重型，慢转向 |
| P-700 | M1.6 / 550 km / 750 kg | 2.20 | 549 | 17 | 领弹协同 |
| P-800 | M2.25 / 300 km / 200 kg | 2.50 | 476 | 4 | 靠穿透+延迟引信，不靠当量 |
| （新）P-1000 Vulkan | 未核（P-500 的增程发展型） | 2.50 | 600 | 22 | 与 P-500 同族，具体参数待核 |
| （新）口径 3M-54 | 未核（亚音速巡航 + 超音速末段） | 2.10 | 450 | 8 | 建议做两段速度 |
| （新）锆石 | 宣称 Mach 9（射程未核） | 3.20 | 600 | 12 | 高超，转向极差 |

- 落点：`MissileProfile` 保留现有 6 参构造器以免破坏 `CbcCompat`（当前 `resolveProfile(stack, p300())` 依赖它）；
  新增 `util/WeaponSpec.java`（record）+ `data/taovmodernnaval/weapons/*.json`（datapack 可覆写）+ 一次性迁移脚本把 11 型 NBT 默认值写进去。
- 验收：新增单测 `WeaponSpecOrderingTest`，断言三条**排序不变量**：
  ① 速度：亚音速组 < P-700 < 超音速组；② 射程：P-15 < P-120/P-270 < P-800 < P-500/P-700；③ 当量：P-800 < P-270 < P-700 < P-500。
  任一被改坏必须测试失败——这是防回归的关键，本轮已两次踩到「符号/量纲」类缺陷。

### P1-1 弹道剖面（2–3 天）

真实数据给了现成的三段高度：巡航（P-270 10–20 m、P-800 数米）、末段（P-270 <7 m）、以及跃升俯冲型。

- 新增 `MissileFlightProfile`（`cruiseAlt`、`terminalAlt`、`diveStartDist`、`popUpHeight`），字段进 `WeaponSpec` 的 JSON。
- 落点：[ShaoMissileProjectile.java](../src/main/java/TAOVMN/entity/ShaoMissileProjectile.java) 的 tick 里加高度保持/末段俯冲两段控制；`seekRange` 之内才切换到末段高度。
- 玩法收益：低空目标更难被远雷达发现（接到 §P2 的探测高度门限），反舰弹「掠海突防」终于成立。
- 验收：单测断言「距离 < diveStartDist 时目标高度收敛到 terminalAlt ±1 格」；游戏内看粒子尾迹。

### P1-2 制导分段与齐射领弹（2 天）

- 现状：指挥仪持续广播（等效无限期中制导）+ 200 tick 过期；P-700/800 是纯自主搜索。
- 真实：惯性 + 指令修正 + 末段主动雷达（P-700 还有反辐射/红外通道）；P-500/P-700 有「领弹高空中继、其余低空突防」的战法。
- 动作：给弹体加 `GuidancePhase { BOOST, INERTIAL, MIDCOURSE, TERMINAL }`；
  末段才开主动导引头（`seekerOnDistance`），中途断链则按惯性记忆飞向最后位置（现有 `inertialTarget` 已经具备雏形）；
  齐射时组内选一枚为领弹（复用现有 64 格广播通道，把「领弹 → 僚弹」的链路写进 `setDirectorTarget` 的一条新重载）。
- 验收：单测断言相位跃迁顺序与「断链后 100 tick 内仍朝记忆点」；不改变无火控时的现有行为。

### P1-3 CIWS 弹药 / 射速 / 命中间（2 天）

- 射速关系纠正：AK-630 应**快于** AK-230（真实 2–2.5 倍）。建议 AK-630 `1 tick/发`、AK-230 `2 tick/发`，
  两者单发伤害按「AK-230 弹丸更重、初速更高」给 AK-230 更高单发（例：AK-630 2.5、AK-230 3.5）。
- 弹药：AK-630 弹链 2000 发、AK-230 每管 500 发；打完必须手动补弹（语言键 `launcher_arm_storage_*` 已经存在但无实现，正好落地）。
- 过热：连续射击 N 秒进入强制冷却；真实 AK-630 是水冷，仍受弹链与炮管寿命限制。
- 命中间：对在飞弹体不再「命中即销毁」，改为「按距离衰减的命中概率 × 弹药消耗」；
  近距离（<20 格）命中率高、远距离低——这才符合「AK-630 拦截窗口短、需要多轮齐射」的真实评价。
- 落点：`AbstractCiwsBlockEntity`（[CiwsSpec](../src/main/java/TAOVMN/block/entity/AbstractCiwsBlockEntity.java) 扩展 rpm/belt/heat/dispersion），两个子类只改参数。
- 验收：单测断言「AK-630 单 tick 期望输出 > AK-230」「弹药耗尽后不再开火」。

### P1-4 分层拦截与目标认领（1–2 天）

- 现状：《防空反导实施报告》已记录「AK630/AK230 与防空弹可能打同一个目标」未解决。
- 动作：给在飞弹体加「已被认领 / 认领者」字段；远程弹（S-300F/Shtil）先认领，CIWS 只打**未被认领且进入自身射程**的目标；
  认领超时（例如目标脱离或弹体死亡）自动释放。
- 验收：单测断言两个拦截器不会选中同一目标；游戏内看「一枚来袭弹只被一条链路接战」。

### P2-1 传感器分工（2–3 天）

- 现状：`radar_block` 一种体制（160 格 / 20 tick）+ `p1_director`（256 格 / 10 tick），没有搜索/跟踪/照射之分。
- 真实：MR-800（远程搜索）→ MR-710（搜索/跟踪）→ 3R41（制导照射）→ MR-123 / MR-104（近防火控）；
  一部 MR-123 可管 2 门炮——这正是 mod 里「发射架就近绑一个雷达」缺的**通道数**概念。
- 动作：给雷达加 `RadarRole { SEARCH, TRACK, FC }` 与 `maxChannels`；搜索雷达只管发现与粗跟踪，火控雷达才能给弹体提供末制导；
  `P1DirectorBlockEntity` 的 64 格广播改成「火控通道占用表」，满通道后拒绝新弹。
- 验收：单测断言通道数上限；火控雷达被摧毁后在飞弹按 §P1-2 回退惯导。

### P2-2 缺失装备（按缺口排序）

### P2-3 数值以外的一致性（半天，顺手清）

- `RadarBlockEntity` 的 IFF 只认 `Enemy`，真实是敌我识别应答；建议改成「阵营标签 + 可选 IFF 开关」，与 `TargetDomain` 对齐。
- `TotalControlBlockEntity` 的 160 格示波器量程与雷达 160 格一致，但指挥仪 256 格——两者不匹配，建议示波器读绑定雷达/指挥仪的实际量程。

## 5. 明确不做

1. **不做真实千米级射程**：MC 视距与服务器负载撑不住（P-500 550 km 换算成 550 000 格）。
   本方案的射程是**对数压缩后的玩法值**，只保证排序与档位关系，图表里已注明。
2. **不改现有物品注册 id**：`p15_missile` 等是存档键与配方键，改名等于砸存档；只改显示名。
3. **不引入完整火控网络协议**：通道数 + 认领已经能表达 80% 的真实行为，组网（G9 拓扑）留给独立一轮。
4. **不做核战斗部**：真实 P-500/P-700 有核型，mod 里没有意义且会破坏平衡。
